# ✅ KUSTOMIZE OVERLAY FIX - ARGOCD COMPATIBLE

**Date**: April 17, 2026  
**Status**: ✅ **FIXED**  
**Error Fixed**: `ConfigMap "X" does not exist; cannot merge or replace`

---

## 🔧 ROOT CAUSE

The overlay `configMapGenerator` and `secretGenerator` were using `behavior: merge` which tries to merge with existing resources. But these resources were not generated by a generator in the base (they existed as regular resource files), causing Kustomize to fail.

---

## ✅ WHAT WAS CHANGED

### ❌ BROKEN (Before)
```yaml
configMapGenerator:
  - name: satmonitor-backend-config
    behavior: merge              # ❌ REMOVED THIS
    literals:
      - keycloak_server_url=...

secretGenerator:
  - name: satmonitor-backend-secrets
    behavior: merge              # ❌ REMOVED THIS
    literals:
      - keycloak_client_secret=...
```

### ✅ FIXED (After)
```yaml
configMapGenerator:
  - name: satmonitor-backend-config
    literals:                    # ✅ No behavior - creates normally
      - keycloak_server_url=...

secretGenerator:
  - name: satmonitor-backend-secrets
    literals:                    # ✅ No behavior - creates normally
      - keycloak_client_secret=...
```

## 📝 WHY THIS FIXES THE ISSUE

1. **Problem**: `behavior: merge` expects a ConfigMap to already exist (from base generators)
2. **Issue**: Base has ConfigMaps as resource files, NOT generators
3. **Solution**: Remove `behavior: merge` to let Kustomize create ConfigMaps normally
4. **Result**: Kustomize generates new ConfigMaps with hash suffixes (e.g., `satmonitor-backend-config-k8m7h9`)
5. **Benefit**: Kustomize automatically updates deployment references to use the correct names

## ✅ ARGOCD COMPATIBILITY

✅ **Before**: ❌ Error - `ConfigMap does not exist; cannot merge`
✅ **After**: ✅ Successfully builds and deploys
